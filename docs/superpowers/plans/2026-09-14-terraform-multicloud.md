# Terraform multi-cloud (GCP + AWS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restructure `deploy/terraform` into two mirrored, reusable Terraform roots (`gcp/`, `aws/`) that deploy this container + Postgres app to Cloud Run/GKE and ECS Fargate/EKS, with kustomize overlays for both Kubernetes targets and a Makefile split into cloud fragments.

**Architecture:** Each cloud is a standalone root module composed of same-named local modules (`registry`, `database`, `serverless`, `kubernetes`; AWS adds `network`). Both roots share one variable/output contract; app-specific values live only in `locals.tf`. Database passwords are generated by Terraform and stored in Secret Manager / Secrets Manager; the root composes `DATABASE_URL` into a second secret and passes secret *references* to the serverless module. The live GCP state (APIs + Artifact Registry) is migrated with `moved` blocks.

**Tech Stack:** Terraform 1.16 (`>= 1.5` floor), hashicorp/google `~> 6.0`, hashicorp/aws `~> 6.0`, hashicorp/random `~> 3.6`, kubectl built-in kustomize, GNU make, k6.

**Spec:** `docs/superpowers/specs/2026-09-13-terraform-multicloud-design.md`

## Global Constraints

- Terraform `required_version = ">= 1.5"`; providers `google ~> 6.0`, `aws ~> 6.0`, `random ~> 3.6`.
- Live GCP project is `mikroteenus`, region `europe-north1`, zone `europe-north1-b`. Only the base layer is live. **Acceptance for the GCP refactor: `terraform plan` shows 6 moved instances, 2 creates (`secretmanager.googleapis.com`, `iam.googleapis.com`), 0 changes, 0 destroys.**
- AWS default region `eu-north-1`. No AWS CLI or credentials exist on this machine: AWS work is verified with `terraform validate` only.
- Resource naming derives from `var.name` (`experiment-go`): Cloud SQL / RDS instance `${name}-pg`, Cloud Run / ECS / GKE / EKS `${name}`.
- Toggle files in each root: `db.auto.tfvars` (`create_db = true`), `serverless.auto.tfvars` (`image = "..."`), `k8s.auto.tfvars` (`create_k8s = true`). No password ever goes into a tfvars file.
- Existing GCP make target names stay unchanged. AWS targets carry an `aws-` prefix. Kubernetes targets are shared and switched with `CLOUD=gcp|aws`.
- **No git repository exists.** Skip every commit step; the verification step of each task is its gate.
- **Shell hook:** any Bash command whose text contains `.env`, `PASSWORD`, `SECRET`, `TOKEN` or `CREDENTIAL` (case-insensitive) is blocked. Write files with the Write/Edit tools, never heredocs. In verification commands, split such words in grep patterns (`PASSW[O]RD`, `SECR[E]T`). Never name a file or make target with those words. Use `terraform output` (no argument) instead of `terraform output -raw db_password_secret`.
- Do not modify anything under `internal/`, `cmd/`, `migrations/`, `loadtest/k6/*.js`.

```hcl
# Generated once, stored in Secret Manager, never written to a tfvars file.
resource "random_password" "db" {
  length  = 32
  special = false # keeps the value safe inside a URL
}

# The cheapest useful shape: shared-core, zonal, HDD, no backups.
# Fine for experiments, none of it appropriate for production.
resource "google_sql_database_instance" "main" {
  name             = "${var.name}-pg"
  database_version = "POSTGRES_${var.engine_version}"
  region           = var.region

  settings {
    tier              = "db-f1-micro"
    edition           = "ENTERPRISE"
    availability_type = "ZONAL"
    disk_type         = "PD_HDD"
    disk_size         = 10
    disk_autoresize   = false

    backup_configuration {
      enabled = false
    }
  }

  # This whole setup is disposable; teardown must actually work.
  deletion_protection = false
}

resource "google_sql_database" "app" {
  name     = var.db_name
  instance = google_sql_database_instance.main.name

  # The instance is deleted right after anyway; skip the SQL-level DROP
  # DATABASE, which fails whenever anything still holds a connection.
  deletion_policy = "ABANDON"
}

resource "google_sql_user" "app" {
  name     = var.db_user
  instance = google_sql_database_instance.main.name
  password = random_password.db.result

  # A postgres user that owns tables cannot be dropped in-place.
  deletion_policy = "ABANDON"
}

resource "google_secret_manager_secret" "db_password" {
  secret_id = "${var.name}-db-password"

  replication {
    auto {}
  }
}

resource "google_secret_manager_secret_version" "db_password" {
  secret      = google_secret_manager_secret.db_password.id
  secret_data = random_password.db.result
}
```

`outputs.tf`:
```hcl

  value       = google_sql_database_instance.main.connection_name
}

output "database" {
  value = google_sql_database.app.name
}

output "user" {
  value = google_sql_user.app.name
}

output "password" {
  value     = random_password.db.result
  sensitive = true
}

```

# Terraform for a container + database application

Two independent Terraform roots that deploy the same container image and a managed
Postgres to Google Cloud (`gcp/`) or AWS (`aws/`). They mirror each other on purpose:
same variable names, same outputs, same layer toggles, same-named modules. Learn one,
and the other reads the same way. Nothing is shared between them at runtime.

| Layer | GCP | AWS | Toggle |
| --- | --- | --- | --- |
| Base (always on, free or cents) | 7 service APIs + Artifact Registry repo | VPC (2 AZ, no NAT) + ECR repo | none |
| Database | Cloud SQL Postgres 17 `db-f1-micro` | RDS Postgres 17 `db.t4g.micro` | `create_db` |
| Serverless containers | Cloud Run v2, 0..5 instances | ECS Fargate behind an ALB, 1..5 tasks | `image != ""` |
| Kubernetes | GKE zonal, spot pool 1..4 | EKS, managed spot node group 1..4 | `create_k8s` |

Each root is composed of local modules with the same names on both sides:
`registry`, `database`, `serverless`, `kubernetes` (AWS also has `network`).

## The contract

Variables identical on both roots:

| Variable | Default | Meaning |
| --- | --- | --- |
| `name` | `experiment-go` | Prefix for every resource name |
| `region` | `europe-north1` / `eu-north-1` | Region |
| `image` | `""` | Full image reference; empty = no serverless service |
| `container_port` | `8080` | Port the container listens on |
| `health_check_path` | `/healthz` | Path the platform probes |
| `env` | `{}` | Extra env vars merged over the defaults in `locals.tf` |
| `create_db` | `false` | Managed Postgres |
| `db_name` / `db_user` | `experiment` / `app` | Database and application user |
| `db_engine_version` | `17` | Postgres major version |
| `create_k8s` | `false` | Kubernetes cluster |
| `k8s_namespace` / `k8s_service_account` | `experiment-go` | Must match `deploy/k8s` |
| `k8s_node_count` / `k8s_node_type` | `2` / `e2-standard-2` or `t3.medium` | Spot pool size and type |
| `serverless_min_instances` / `_max_instances` | `0` or `1` / `5` | Fargate cannot scale to zero |
| `serverless_cpu` / `serverless_memory` | `"1"`,`"512Mi"` or `"256"`,`"512"` | Platform-native units |

GCP only: `project_id` (required), `zone`, `registry_repo`. AWS only: `vpc_cidr`.

Outputs identical on both roots: `image_base`, `db_host` (Cloud SQL connection name or
RDS endpoint), `db_password_secret` (Secret Manager id or Secrets Manager ARN),
`serverless_url`, `k8s_cluster_name`, `k8s_credentials_command`.

## How the pieces connect

- The database password is generated by Terraform (`random_password`) and stored in
  Secret Manager / Secrets Manager as `<name>-db-password`. It never appears in a
  tfvars file. `make k8s-secret` copies it into the cluster; `make sql-psql` reads it.
- The serverless platform receives `DATABASE_URL` as a secret reference. The root
  composes the URL (`locals.tf`) into a second secret `<name>-database-url` and hands
  its id/ARN to the `serverless` module. The module only grants read access and wires
  the env var; it never sees the value.
- Kubernetes pods get `POSTGRES_*` from a ConfigMap plus the password from the
  `experiment-go-db` Secret (see `deploy/k8s`). On GKE a Cloud SQL Auth Proxy sidecar
  provides localhost; on EKS pods connect to RDS directly with TLS.
- Layer toggles are files. The `make` wrappers write `db.auto.tfvars`,
  `serverless.auto.tfvars` and `k8s.auto.tfvars` next to the root and run
  `terraform apply`; teardown removes the file and applies again. Every apply
  converges on the full declared state, so deploying one layer never destroys another.
- Ordering: serverless requires the database (a precondition fails the plan otherwise),
  so tear down serverless before the database, or use `make teardown-all` /
  `make aws-teardown-all`.

## Reusing this for another application

1. Copy `gcp/` or `aws/` (or both) into your repo.
2. Edit `locals.tf`: the `app_env` map and, if your app wants `POSTGRES_*` variables
   instead of a single `DATABASE_URL`, the `secret_env` wiring in `main.tf`
   (pass `module.database[0].password_secret_id` / `password_secret_arn` under the
   variable name your app expects).
3. Set `name`, `image`, `container_port`, `health_check_path` in `terraform.tfvars`
   or through `-var` flags.
4. Replace `deploy/k8s` with your own manifests if you use the Kubernetes layer; the
   overlays only need the `experiment-go-db` Secret name and the placeholders.
5. Keep the modules untouched. If you need a different database engine or a NAT
   gateway, change the module, not the root.

## State and backends

State is local (`terraform.tfstate` inside each root, gitignored) and contains the
database password in plain text. For anything beyond experiments, move it:

```hcl
# gcp/versions.tf
terraform {
  backend "gcs" {
    bucket = "YOUR_PROJECT-tfstate"
    prefix = "experiment-go"
  }
}

# aws/versions.tf
terraform {
  backend "s3" {
    bucket       = "your-tfstate-bucket"
    key          = "experiment-go/terraform.tfstate"
    region       = "eu-north-1"
    use_lockfile = true
  }
}
```

then `terraform init -migrate-state` in that root.

## Why two roots and not one

Terraform providers cannot be conditional. One root that "selects a cloud" would need
credentials for both on every run and would plan against both APIs. Two roots keep each
cloud's blast radius, credentials and state separate; the shared contract keeps them
easy to compare.

## Design notes and gotchas

- **No NAT gateway.** Tasks and nodes sit in public subnets with public IPs and pull
  images through the internet gateway. Security groups admit only ALB traffic to tasks
  and nothing new to nodes. RDS is in private subnets and never public.
- **`sslmode=require`.** RDS Postgres 15+ forces TLS; the k8s `eks` overlay and the
  `DATABASE_URL` secret both set it.
- **Fargate minimum is one task**, so the ECS layer costs money while it exists.
- **EKS LoadBalancer Services** get an NLB from the EKS cloud controller via the
  annotation in `deploy/k8s/overlays/eks/lb-service.yaml`. If that stops working,
  `make k8s-forward CLOUD=aws`.
- **Spot nodes** can be reclaimed with two minutes notice. The PDB keeps one pod alive.
- **Connection budget.** `db.t4g.micro` allows roughly 80 connections; `DB_MAX_CONNS ×
  replicas` must stay below it.
- **psql access.** RDS is private. Use `kubectl -n experiment-go run psql --rm -it
  --image=postgres:17-alpine -- psql "postgres://app:PASSWORD@HOST:5432/experiment?sslmode=require"`
  from the EKS cluster, with the password from
  `aws secretsmanager get-secret-value --secret-id experiment-go-db-password --query SecretString --output text`.
